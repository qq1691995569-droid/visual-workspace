# 画布功能配置后台

后台地址：http://127.0.0.1:5173/admin 。随当前本机画板开发服务运行，没有画布菜单入口。
这不是已经部署的多人在线后台，也未复用 DREO 管理员身份。

## 登录与使用

首次启动自动生成 `.canvas-data/config-admin-key.txt`，将本机文件中的管理口令填入后台。
口令只保存在页面内存，刷新后重新输入。删除或更换该文件中的口令即可使旧口令失效。
不要把口令放进网址、GitHub 或同事安装包。

选择左侧功能，编辑 AI 人设及 Skill 正文，点击“保存草稿”。确认内容可以公开分发后点击“发布到 GitHub”。
发布仅提交 `published/canvas-functions.json` 到 `qq1691995569-droid/visual-workspace` 的 main 分支，使用本机已有 Git 登录权限。
程序在临时独立工作目录提交，不提交当前工作区的其他文件，不强推。网络、权限或远端版本冲突时保留草稿并提示失败。
“历史版本 → 以此版本重新发布”创建更高编号的新版本，不覆盖历史，也不会重新执行旧任务。

例如：选择“模型替换”，在规则中补充“参考床具带床品时整体替换；没有床品时不沿用旧床品”，保存草稿并发布。
同事的新任务获取新版本后会使用这条规则。已经提交的任务保持原来的配置快照。

## 同事如何同步

同事必须先更新一次包含配置同步模块的画板程序。旧版本不会自动获得这个能力。
新版服务在收到请求时检查 GitHub 上的发布文件，两次检查间隔至少 60 秒；GitHub 缓存和网络可能造成延迟，不是实时推送。
下载后先校验，成功才替换本机正式配置。未发布时沿用内置规则；网络不可用或配置无效时保留上次有效配置。
配置公开分发，同事能读取它；同事自己的管理口令不代表有你的 GitHub 仓库写权限。
更改本地源码的人仍然可以修改自己的行为，不承诺 DRM 或不可绕过的客户端停用。

## 本版管理范围

- 风格转换：沿用已有规则，首次打开迁移本机已启用的风格规则。
- 模型替换：编辑实际执行的 Skill 正文。
- 图片编辑、参考生图、白底图、去背景、消除、变清晰、扩图、室内分层：编辑现有 Skill 正文及人设。
- 材质优化、光影调整：添加人设和补充规则；结构约束、参数解释及图像合成仍由程序管理。
- 停用上述功能会在服务端拒绝其新任务；已有节点可以保留，停用不是删除功能或取消已提交任务。
- 本地调色算法、DREO/Liblib 工作流参数、模型接入和新增执行器仍需要程序更新，不在本版文本配置范围内。
- 不修改 DREO 用户、扣费、远端任务或历史。

## 存储和备份

- `.canvas-data/function-config.json`：草稿、正式版本、历史版本和发布记录。
- `.canvas-data/config-admin-key.txt`：独立本机管理口令。
- `.canvas-data/` 原有任务文件：保留任务及所用功能配置快照；原有图片存储路径不变。
- GitHub：程序代码与公开发布配置。私有数据目录、密钥、图片、日志、备份均不应提交。

备份时在没有发布或保存操作的情况下，复制 `.canvas-data/function-config.json` 到私有备份位置；备份管理口令时同样按凭据保管。
只恢复本地文件不会回退同事已同步的版本；面向同事的回退请使用后台重新发布。

## 安全边界

所有新管理 API 要求 Bearer 管理口令；未提供返回 401，错误口令返回 403。
旧的无鉴权管理 API 已关闭。继续要求本机来源、合法 Host、同源 Origin，不开放局域网监听。
Vite 禁止直接读取私有数据和运行目录。后台没有第二套用户密码系统，不依据电脑用户名或浏览器声明的管理员身份授权。
这是本机开发阶段方案，若以后开放多人网页服务，需另做可信用户身份接入和生产部署。

## 默认关闭后台

标准安装默认关闭 `/admin` 页面和管理 API，直接访问返回 404。画布没有后台入口；功能配置同步仍然正常。
只有需要管理的本机，在不提交 Git 的 `.env.local` 中设置 `CANVAS_ADMIN_ENABLED=1` 并重启服务，才会开放后台；开放后仍需本机管理口令。
不要把 `.env.local`、`.canvas-data`、凭据或数据库分发给同事。源码使用者可以修改自己的副本，这个开关不限制他们管理自己的电脑；不能取得你的后台数据或 GitHub 写权限。
## 放大工作流与本机共享

后台的「放大工作流」直接读取本机 `.canvas-data/liblib.json`，沿用现有凭据引用。名称、启停、默认项和 API 参数可编辑；先保存草稿，再发布到本机服务。草稿存于 `.canvas-data/upscale-draft.json`，发布递增工作流版本并保留历史；回退先恢复为草稿，再发布。旧任务保留原工作流快照。此功能不通过 GitHub 分发密钥。

共享入口是独立 HTTPS 服务（5443），画布和管理后台仍仅监听本机。主机需同时运行原有 5173 服务和 `Start-UpscaleSharing.cmd`。服务只提供工作流目录、放大提交和原任务查询，不提供 DREO 或管理接口。

首次初始化：在已安装 Python cryptography 的环境执行 `python scripts/setup-upscale-sharing.py --host 本机局域网IP`。脚本生成本机私有证书、密钥和 `.canvas-data/upscale-sharing.json`，不会覆盖已有配置。证书有效期一年；地址改变或证书更新时需重新配置并重新发放连接文件。当前实现不自动续期，也不自动开机启动。

如防火墙阻挡，在管理员 PowerShell 中执行 `scripts/Allow-UpscaleSharing.ps1`。规则仅适用于域/专用网络、本地子网、TCP 5443，不开放画布后台。跨子网访问需要公司 IT 单独确认。

管理员在后台「同事共享访问」输入同事名称，创建并下载专属 `upscale-connection.json`。仅把该文件交给对应同事；同事更新程序后把文件放入项目 `.canvas-data/` 并重启。文件包含共享访问凭据与服务器证书，不含 Liblib 密钥，不应提交 Git。后台可以撤销单个凭据，撤销立即生效；这不会取消已提交的远端任务。此方式是持有凭据授权，不是 DREO 用户身份认证，请勿共用连接文件。

同事的放大请求经过自己的本机后端转发给主机，服务器证书必须验证通过。任务归属保存在主机 `.canvas-data/shared-owners/`，结果和记录沿用主机本地任务存储；每个访问凭据只能查询自己的任务。管理后台可查看主机任务。若主机断网、关机或服务退出，同事无法放大；已有任务不要重新提交，恢复连接后查询原任务。

工作流目录在画布聚焦时和每分钟刷新，提交时再次检查版本与开关。共享任务使用主机 Liblib 账号的额度与并发；不写入 DREO 历史。备份整个主机 `.canvas-data/` 及外部凭据文件，备份仅由管理员保管。
